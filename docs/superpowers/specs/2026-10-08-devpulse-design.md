# DevPulse — design

Date: 2026-10-08 · Status: approved in brainstorming, awaiting spec review

## 1. Intent

A personal macOS utility for this Mac (Apple M4, 16 GB, macOS 26.5) that answers two
questions at a glance and lets you act on them:

- **Is the machine OK right now?** RAM and disk state in the menu bar, colour-coded.
- **What is eating it, and can I get rid of it?** Processes (kill / relaunch) and the
  largest files/folders in `~` (delete / reveal in Finder).

Both concerns — RAM/processes and disk — have equal priority.

**Stated by the user:** personal use only, no sandbox, source in a GitHub repo
(account `peppperrroni`); status-bar icon with popover showing RAM, disk, top-5
processes, top-5 files/folders; main window = dev cleaner with two tabs (Processes,
Files); deletion is permanent with confirmation; the scan covers all of `~` in the
background every N hours with a cached result and a rescan button; visual style after
getartcraft.com.

**Assumed (accepted):** "память" = disk, "оперативка" = RAM; macOS 26+, Apple Silicon,
Swift 6, SwiftUI; works without Full Disk Access and suggests enabling it when much of
`~/Library` is unreadable.

**Success:** the menu-bar indicator tells state without opening anything; from the
popover it takes one click to see what uses RAM or disk; killing a runaway process or
deleting a cache takes two clicks plus a confirmation; nothing outside `~` or a
protected root can ever be deleted.

**Non-goals:** distribution, signing/notarization, App Store, CPU/GPU/network/battery
graphs, history charts, curated cache rules, deletion to Trash, a drill-down disk tree.

## 2. Architecture

Two parts:

- **`DevPulseCore`** — local Swift package, no UI, all logic, tested with `swift test`.
  - `SystemSampler` — every 2 s: RAM (used / wired / compressed via `host_statistics64`,
    pressure via `kern.memorystatus_vm_pressure_level`) and disk (total / free via
    `URLResourceValues.volumeAvailableCapacityForImportantUsage` on `/`).
  - `ProcessService` — list of current-user processes via `libproc`
    (`proc_listpids`, `proc_pidinfo`, `proc_pid_rusage`): pid, name, path, RSS
    (`ri_phys_footprint`), CPU % (delta of `ri_user_time + ri_system_time` between
    samples), and whether it is a GUI app (matched against
    `NSWorkspace.shared.runningApplications`). `java` processes are named by their
    main class or jar from `KERN_PROCARGS2` (otherwise every Gradle/Kotlin daemon
    reads `java`). Actions: `terminate`, `forceKill`, `relaunch`.
  - `DiskScanner` — background, cancellable scan of `~` with progress; produces a
    size tree; persists to `~/Library/Caches/DevPulse/scan.json`.
  - `TopItems` — pure function: size tree → ranked files and folders (§4).
  - `Deleter` — `validate(path)` then permanent removal (§6).
  - `HealthEvaluator` — pure function: metrics → `good | warn | bad` per indicator.
- **`DevPulseApp`** — Xcode project generated by XcodeGen (`project.yml`; no
  `.pbxproj` in git). `NSStatusItem` with an attributed title, an `NSPopover` and an
  `NSWindow` with two tabs, both hosting SwiftUI (a `MenuBarExtra` label cannot mix
  coloured dots with menu-bar-adaptive text), and `@Observable @MainActor` stores fed by Core. `LSUIElement = YES` (no Dock icon).

Data flow: `SystemSampler / ProcessService / DiskScanner → Store (@Observable,
MainActor) → MenuBarLabel / Popover / Window`.

Process sampling runs only while the popover or window is visible; the status-bar
label needs only `SystemSampler`, which is cheap.

## 3. Menu-bar indicator

Two indicators separated by a slash, each a coloured dot and a percentage, no words:

    ● 62% / ● 71%
    RAM     disk used

The title is an `NSAttributedString`: `●` runs carry the health colour, the text uses
`labelColor` and so adapts to the menu bar over any wallpaper. Digits are monospaced
(`monospacedDigitSystemFont`), so the width does not jitter.

| colour | RAM (pressure level) | Disk (free space) |
|---|---|---|
| green `#4caf50` | normal | ≥ 20 % and ≥ 30 GB |
| amber `#ffb347` | warn | < 20 % or < 30 GB |
| red `#b3261e` | critical | < 10 GB |

The RAM percentage is `(used + wired + compressed) / total`, for display only. The
colour comes from memory pressure, not from the percentage, because macOS keeps RAM
full of cache and a high percentage alone means nothing. The disk percentage is
`used / total`.

## 4. Disk scanner and the top list

**Walk.** `FileManager.enumerator(at: ~)` with keys `totalFileAllocatedSize`,
`isDirectory`, `isPackage`, `isSymbolicLink`, `fileResourceIdentifier`,
`contentModificationDate`.
- Symlinks are not followed.
- Packages (`.app`, `.xcarchive`, `.photoslibrary`, …) are treated as one item (a
  "file") whose size is the sum of their contents.
- Hard links are counted once (dedup by `fileResourceIdentifier`). APFS clones may be
  counted twice; this is accepted and documented.
- Dataless iCloud files have an allocated size of 0 and never rank.
- Unreadable directories increment a `skipped` counter and are listed. If skipped
  entries under `~/Library` exceed 20, the Files tab shows a hint to grant Full Disk
  Access, with a button that opens System Settings.
- Runs in `Task(priority: .utility)`, cancellable, and reports progress (bytes and
  item count).
- Schedule: every N hours (default 6, setting in the window), on launch if the cache is
  older than N, and on the "Rescan" button.

**Cache.** Only nodes ≥ 50 MB (files and folders) are kept, with path, size, kind,
mtime, scan date and the `skipped` list. After a deletion the deleted size is
subtracted from every cached ancestor and the node is removed, with no rescan. A cache
that is corrupt or has the wrong schema version is discarded and a rescan runs.

**Ranking (`TopItems`).**
- **Files:** the largest individual files, packages included.
- **Folders:** a folder is a *candidate* if no child folder holds ≥ 50 % of its size.
  This is where the weight actually sits. Example: `~/Library/Developer/Xcode/DerivedData`
  is a candidate, `~/Library/Developer` is not.
- Candidates are taken greedily by size and skipped when they are an ancestor or
  descendant of one already chosen.
- Protected roots are never candidates: `~`, `~/Library`, `~/Documents`, `~/Desktop`,
  `~/Downloads`, `~/Pictures`, `~/Movies`, `~/Music`, `~/Applications`,
  `~/Library/Containers`, `~/Library/Group Containers`, `~/Library/Mobile Documents`.
- "All" merges files and folders by size. Here a file inside a chosen folder still
  appears on its own, because removing it is a different action.
- Popover: top 5 of "All". Files tab: top 50 with the filter All / Files / Folders.

## 5. UI

Visual language after getartcraft.com. Tokens are defined once and used everywhere:

| token | light | dark |
|---|---|---|
| `bg` | `#f2f1ee` | `#101014` |
| `raised` | `#faf9f7` | `#1a1a20` |
| `sunken` | `#e9e8e4` | `#0a0a0d` |
| `ink` | `#101014` | `#f2f1ee` |
| `mute` | `#6b6a66` | `#8d8c88` |
| `accent` | `#2d81ff` | `#2d81ff` |
| `danger` | `#b3261e` | `#b3261e` |

Fonts: **SF heavy expanded** for numeric headings, **Inter** (bundled, OFL) for body,
**Geist Mono** (bundled, OFL) for labels, numbers and section markers, **New York
italic** for small accents. Archivo and Instrument Serif were the site's choice but
have no Cyrillic glyphs (checked with CoreText), and the UI copy is Russian. If a font fails to load, SF is used. Section markers follow the
site: `01 / Процессы`, numbered rows `01…05`. The theme follows the system.

**Popover (variant B, ~340 pt tall, 340 pt wide).**
- Header: "DevPulse" plus a one-line serif status ("всё спокойно" / "память под
  давлением" / "мало места").
- Two compact gauges in a row: RAM (GB used, meter coloured by pressure) and Disk
  (GB free, accent meter).
- Segmented control **Процессы / Диск**, then 5 numbered rows (name + RAM, or
  path + size).
- Footer: "скан N ч назад" and an **Открыть cleaner** button.
- Clicking a row opens the window on the matching tab with that row selected.

**Window (variant A, segmented tabs on top).**
- *Processes tab:* header `01 / Процессы · <count>` with total used RAM, the segmented
  control on the right, a filter field, and actions on the selected row:
  **Перезапустить** (enabled for GUI apps only) and **Завершить** (danger).
- The process table has columns Name, Type (`app` / `proc` chip), RAM, CPU. It is
  sortable, sorted by RAM descending by default, and refreshes every 2 s while the
  window is visible. Multi-select is allowed for Завершить.
- *Files tab:* header `02 / Файлы · скан N ч назад · ⟳` showing free and total GB,
  progress while scanning, a filter All / Files / Folders, and actions
  **Показать в Finder** and **Удалить навсегда** (danger).
- The files table has columns Path (`~`-abbreviated, middle truncation), Size,
  Modified. Multi-select is allowed.
- Settings (scan interval, «Запускать при входе») is a small popover from a gear in
  the window toolbar. There is no separate settings window.
- Launch at login uses `SMAppService.mainApp`. It is switched on once, on the first
  launch of the `/Applications` copy (`scripts/install.sh`). After that the toggle is
  the user's, and development builds are never registered.

## 6. Errors and action safety

**Terminate.**
- SIGTERM first (for GUI apps, `NSRunningApplication.terminate()`).
- If the process is still alive after 3 s, the row offers **Убить принудительно**
  (SIGKILL). It is never escalated automatically.
- `EPERM` / `ESRCH` are shown inline on the row ("нет прав" / "уже завершён").
- DevPulse's own pid and pids < 100 are not actionable.

**Relaunch (GUI apps only).** Capture the `bundleURL`, call `terminate()`, wait up to
10 s for exit, then `NSWorkspace.openApplication(at:)`. If the app does not exit in
time, the relaunch is aborted with a warning and nothing is force-killed.

**Delete (permanent).**
- A confirmation sheet lists the paths and total size and says "удаление необратимо".
- Right before removal, `Deleter.validate` re-checks each path:
  - after `resolvingSymlinksInPath`, the path is strictly inside `~`;
  - it is not a protected root (§4) and not an ancestor of one;
  - it exists.
- A path that fails validation is refused, never removed.
- Removal is `FileManager.removeItem`. Partial failure reports "освобождено X ГБ, не
  удалось: …".

**Scanner.** Errors never abort a scan (see §4). Cancellation keeps the previous cache.

## 7. Testing

Swift Testing in `DevPulseCore`:
- `HealthEvaluator`: each threshold boundary for RAM and disk.
- `TopItems`: the 50 % rule, ancestor/descendant exclusion, protected roots, merge
  order — on synthetic trees.
- `Deleter.validate`: protected roots, paths outside `~`, `..` traversal, a symlink
  inside `~` pointing outside, non-existent paths.
- `DiskScanner`: a temporary directory with files of known size, a package, a hard
  link, a symlink loop, an unreadable folder.
- Cache: round-trip, ancestor subtraction after delete, corrupt file discarded.
- `ProcessService`: smoke test that the current process appears with non-zero RSS.
- `SystemSampler`: smoke test that values are within sane bounds.

Defects are reproduced with a failing test first (per CLAUDE.md). UI is verified
manually by running the app.
